## Lint checks

| App | `pnpm run lint` (before this pass) | After |
|---|---|---|
| `apps/api` | ✅ exit 0 | ✅ exit 0 |
| `apps/storefront` | ❌ exit 1 (1 error) | ✅ exit 0 |
| `apps/admin` | ❌ exit 1 (1 error) | ✅ exit 0 |

The single error in each frontend app was the auto-generated `next-env.d.ts` tripping
its own `@typescript-eslint/triple-slash-reference` rule — not hand-written code, and
regenerated by Next.js itself on every run. Fixed by adding `next-env.d.ts` to the
shared root `.eslintrc.json`'s `ignorePatterns` (one line, applies to both apps via
their `extends`) rather than editing a file Next.js owns and regenerates. Remaining
output is pre-existing `@typescript-eslint/no-explicit-any` / `no-unused-vars`
**warnings** only (6 in storefront, 19 in admin) — not errors, not touched this pass
(see `CODE-AUDIT.md` for why: fixing them means touching working code for a purely
cosmetic gain, out of scope for a hardening pass that should "not rewrite working code
unnecessarily").

Known gotcha hit and resolved during this pass (documented, recurring, not a regression):
running `pnpm run build` in the same app directory as a running `pnpm run dev --watch`
process corrupts that dev server's `dist`/`.next` output mid-recompile. All three dev
servers crashed as a side effect of the build runs above and were restarted cleanly
afterward (kill stale processes, `rm -rf dist`/`.next`, restart) — the production
builds themselves were unaffected and all still report exit 0.
